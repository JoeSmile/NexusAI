# 角色旅程 01 — user(业务用户)

> 来源: Task 30 五角色评审的延伸——权限矩阵只验证"能不能访问",旅程验证"干活顺不顺"。
> 形式: 任务驱动剧本,不是 curl 清单。curl 仅作辅助验证,主角是"人走流程"。
> 前置: `make seed` 已建 acme/alice(user key);后端已起(`make run`)。
> key: `QA_KEY`(user)。

## 角色画像

某业务部门员工(如采购部专员),会用聊天工具,不懂技术。
日常目标: 用 AI 查内部知识、查数据、写东西——**不关心系统怎么实现**。

## 任务清单

### 任务 1.1 首次使用: 我到底能用什么?

| 步 | 操作(人视角) | 实际端点 | 预期 |
|----|--------------|----------|------|
| 1 | 拿 key 登录/填 key | `GET /api/health` | 通过 |
| 2 | 想看看系统有什么能力 | `GET /api/capabilities`(T30 后)/ playground 首页 | 能列出"我"能用的能力 |
| 3 | 想用 RAG 问知识库 | `POST /api/rag/ask` | 有答案 |

**别扭点记录(重点观察):**
- [ ] 登录后有没有"你能做什么"的引导?还是空白的?
- [ ] 能力列表是否按 user 角色过滤了?(不该看到 admin 才有的东西)
- [ ] 问 RAG 之前,user 怎么知道知识库里有没有内容?

### 任务 1.2 权限被拒: 我想用但没权限

| 步 | 操作 | 实际端点 | 预期 |
|----|------|----------|------|
| 1 | 用 user key 调 `GET /api/admin/api-keys` | `GET /api/admin/api-keys` | 403 |
| 2 | 403 之后,user 有什么"可行动"的下一步? | `POST /api/admin/permissions/request` | 能提交申请(8.5 已实现) |

**别扭点记录:**
- [ ] 403 响应是"裸错误码"还是"告诉你该怎么办"?(如 AUTH_002 + 申请入口提示)
- [ ] 申请提交后,user 能看到"进行中"状态吗?还是石沉大海?
- [ ] 申请表单里"权限/资源"字段,业务用户看得懂吗?

### 任务 1.3 用 AI 干活: 一次真实的问答

| 步 | 操作 | 实际端点 | 预期 |
|----|------|----------|------|
| 1 | 问一个企业问题(如"信息安全管理制度讲了啥") | `POST /api/rag/ask` | 有答案 + 来源 |
| 2 | 追问一个相关话题(多轮) | `POST /api/rag/ask/context` | 记住上文 |
| 3 | 答案里有没有"数据来自哪"的标注? | 响应体 | 可溯源 |
| 4 | 回答不满意,想反馈 | `POST /api/feedback/` | 能提交 |

**别扭点记录:**
- [ ] 答案有没有来源/引用?业务用户信任的依据是什么?
- [ ] 反馈入口对 user 是"在手边"还是"要找半天"?
- [ ] 多轮对话里,user 怎么知道系统"记得"什么?(记忆系统可见性)

### 任务 1.4 想查自己的使用情况

| 步 | 操作 | 实际端点 | 预期 |
|----|------|----------|------|
| 1 | 查自己的记忆/画像 | `GET /memory/users/{user_id}/memories` + `/profile` | 有数据 |
| 2 | 想删掉某条被记错的记忆 | `DELETE /memory/users/{user_id}/memories/{id}` | 能删 |

**别扭点记录:**
- [ ] 业务用户会主动查"记忆"吗?这个功能对 user 的入口在哪里?
- [ ] 删除记忆后,是否立即影响后续回答?(还是缓存里还有?)
